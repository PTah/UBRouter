# UBrouter — техническое задание

**Продукт:** интерактивный установщик и набор модулей для превращения Ubuntu Server 24.04 LTS в полноценный маршрутизатор.  
**Версия продукта:** 1.0.0 · **ТЗ:** актуализировано под 1.0 (детальный flow — [02-wizard-flow.md](02-wizard-flow.md), решения — [DECISIONS.md](DECISIONS.md)).  
**Репозиторий:** https://github.com/PTah/UBrouter

> Исторические разделы ниже (§4–§13) могут содержать формулировки эпохи MVP; при расхождении приоритет у кода, README и docs/01–05 / 02-wizard-flow.

## 1. Цель и границы

### 1.1. Цель

Пользователь ставит Ubuntu Server 24.04 на железо с ≥2 сетевыми портами (или VM с vNIC), запускает один входной скрипт и через опросник получает рабочий роутер:

- WAN с интернетом (в т.ч. Multi-WAN failover/LB)
- LAN (один порт или bridge) со шлюзом
- NAT / firewall (в т.ч. port-knock)
- по желанию: DNS, DHCP (+теги), NTP, VPN, QoS, IGMP/IPTV, OSPF, hardening, Netwatch/Telegram
- IPv6 dual-stack (off / dhcpv6 / slaac) + LAN RA
- обход блокировок / selective routing (`bypass-policy`)

Все ответы — в `answers.yaml`; повторный apply идемпотентен; cleanup при удалении туннелей/Y→N.

### 1.2. Не цель (никогда / вне scope)

| Исключено | Почему |
|-----------|--------|
| Wi‑Fi AP / CAPsMAN / mesh | продукт = проводной роутер |
| Web UI | только CLI wizard + модули |
| PPTP | небезопасно |
| L2TP server | out of product (client — есть) |
| SIP ALG apply | флаг возможен; настройка руками |
| Полный клон RouterOS | не паритет фич |
| Автомиграция из `.rsc` MikroTik | не обязательна |
| BGP / VRRP / HA | вне 1.0 |

**В 1.0 есть (раньше «позже»):** IPv6 dual-stack, optional OSPF (FRR).

### 1.3. Целевая аудитория

- Домашний / SOHO пользователь, которому нужен «MikroTik-лайт» на Ubuntu
- Админ, который хочет воспроизводимый netplan+nftables+dnsmasq без ручной возни

## 2. Принципы продукта

1. **Wizard-first.** Первичный UX — вопросы; silent mode через `answers.yaml`.
2. **Имена интерфейсов — единый контракт.** Решение на шаге 1 фиксируется в answers и используется во всех модулях (netplan, nft, dnsmasq, VPN, QoS).
3. **Модульность.** Каждый сервис — модуль `detect → plan → apply → verify → rollback`.
4. **Минимализм по умолчанию.** «Нет» на необязательный сервис = модуль не ставится.
5. **Безопасный fail.** Перед apply — baseline доступности (интернет / LAN / DNS / VPN по наличию), snapshot конфигов; после apply — прогон healthcheck до **60 с** с **автоматическим откатом** к snapshot, если связь упала или хуже baseline; плюс ручной `ubrouter rollback`.
6. **Без секретов в git.** Пароли VPN/PPPoE — только в answers.local (gitignore) или prompt.
7. **Ubuntu 24.04 LTS amd64** — единственная поддерживаемая ОС в v1.
8. **Root/sudo обязателен** для apply; wizard может собирать answers без apply. Пользователь, от которого запускают установку и cron/хуки, должен иметь **passwordless sudo** (см. ниже).

#### 2.8. Passwordless sudo для пользователя UBrouter

Скрипты apply/rollback меняют netplan, nftables, systemd — им нужен root. Чтобы не вводить пароль на каждый шаг (и чтобы работали неинтерактивные apply), добавьте пользователя в sudoers без пароля.

Пример (подставьте свой логин вместо `ubrouter`):

```bash
# от root или через sudo -i
install -d -m 0750 /etc/sudoers.d
cat >/etc/sudoers.d/ubrouter <<'EOF'
# UBrouter: пользователь запуска wizard/apply без пароля
ubrouter ALL=(root) NOPASSWD: ALL
EOF
chmod 0440 /etc/sudoers.d/ubrouter
visudo -cf /etc/sudoers.d/ubrouter
```

Проверка:

```bash
sudo -n true && echo "passwordless sudo OK"
```

Уже будучи в группе `sudo`, можно ограничить права только нужными командами (`/opt/ubrouter/install.sh`, `netplan`, `nft`, `systemctl`, …) — полный `NOPASSWD: ALL` проще для домашнего роутера, но шире по атакующей поверхности.

## 3. Высокоуровневая архитектура

```text
┌─────────────────────────────────────────────────────────┐
│  install.sh / ubrouter wizard                            │
│    phases 01..N  →  answers.yaml                         │
└───────────────────────────┬─────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│  apply.sh  (baseline → snapshot → modules → health 60s)  │
│    modules/*  plan → apply → verify; auto-rollback       │
└───────────────────────────┬─────────────────────────────┘
                            │
     ┌──────────┬───────────┼───────────┬──────────┐
     ▼          ▼           ▼           ▼          ▼
  netplan    nftables    dnsmasq     chrony     vpn/*
  (WAN/LAN)  (NAT/fw)    (DNS/DHCP)  (NTP)    gre/wg/...
```

**Артефакты на хосте (после установки):**

| Путь | Назначение |
|------|------------|
| `/etc/ubrouter/answers.yaml` | зафиксированные ответы |
| `/etc/ubrouter/state.json` | применённые модули, версии |
| `/var/lib/ubrouter/snapshots/` | бэкапы до apply |
| `/usr/local/lib/ubrouter/` | модули и lib (или `/opt/ubrouter`) |

Рекомендуемый workdir разработки: `/opt/ubrouter` (копия репо).

## 4. Опросник (фазы wizard)

Порядок строго последовательный: каждая фаза может зависеть от предыдущих.

### Фаза 01 — Именование интерфейсов

**Вопрос:** как называть сетевые интерфейсы?

| Вариант | Поведение |
|---------|-----------|
| `keep` | оставить имена ядра (`enp1s0`, `ens18`, …) |
| `eth` | переименовать в `eth0`, `eth1`, `eth2`, … |
| `ether` | переименовать в `ether0`, `ether1`, … (стиль MikroTik) |
| `custom` | префикс задаёт пользователь (`lan0`/`wan0` и т.п. — через карту ролей, см. ниже) |

**Детали:**

- Показать текущие NIC: имя, MAC, carrier, PCI/bus, скорость.
- Порядок нумерации: по PCI slot / по MAC / вручную (перестановка).
- Реализация rename: udev/netplan `set-name`.
- После rename — reboot или `netplan apply` + проверка, что имена совпали.
- В `answers.yaml`: `interfaces.naming`, `interfaces.map[]` `{ mac, name, role? }`.

**Инвариант:** дальше везде только выбранные имена.

### Фаза 02 — Роли портов (WAN / LAN / OPT)

**Вопросы:**

1. WAN — какой порт? (по умолчанию первый в map / eth0)
2. LAN — один порт или несколько в bridge?
3. Если bridge: какие порты в `br-lan`? Имя bridge фиксировано `br-lan` (или спросить).
4. Опционально: порт `mgmt` / `opt` (без DHCP-сервера, для отката/сервисной сети)

**Ограничения v1:**

- Ровно один WAN (primary).
- Один LAN-сегмент (один L3-шлюз).
- Bridge только для LAN-портов (не WAN).

### Фаза 03 — Интернет на WAN

**Режим WAN:**

| Режим | Параметры |
|-------|-----------|
| `dhcp` | client DHCP; опционально hostname, client-id, MAC clone |
| `static` | address/prefix, gateway, DNS (1–3), optional metric |
| `pppoe` | interface VLAN? username/password, MTU, service-name |
| `ipoe` | client IPoE (если нужен отдельный netdev; иначе часто = dhcp) |
| `none` | WAN без L3 сейчас (только для lab) |

**Дополнительно:**

- VLAN на WAN (`wan.vlan_id`) — часто для ISP.
- MTU WAN (auto / 1500 / 1492 PPPoE / custom).
- IPv6 WAN (v1.1): off / dhcpv6 / slaac — в v1 по умолчанию `off`.

### Фаза 04 — LAN L3

**Вопросы:**

- Подсеть LAN (CIDR), адрес шлюза на роутере
- Включить ли DHCP-сервер? (если да — пул, lease time)
- DNS клиентам: этот роутер / внешние / свой список
- NTP клиентам: этот роутер / внешние / выкл
- Domain / search domain

**Defaults (безопасные):**

- `10.0.0.1/24`, gateway `.1`
- DHCP pool `.100–.200`
- DNS/NTP → роутер, если службы включены

### Фаза 05 — Службы ядра (вкл/выкл)

Для каждой службы: «Настроить? [Y/n]» + подвопросы при Y.

| Служба | Пакет / реализация | Подвопросы |
|--------|--------------------|------------|
| DNS resolver для LAN | dnsmasq (default) или unbound+dnsmasq | upstream servers, cache size, blocklists? |
| DHCP server | dnsmasq | pool, static leases file, options 3/6/42 |
| NTP | chrony | upstream pools (distro default / custom) |
| NAT masquerade | nftables | всегда рекомендуется при private LAN |
| Firewall baseline | nftables | drop new from WAN; allow established; allow LAN→WAN |
| IP forwarding | sysctl | обязательно при Y на NAT/router |

### Фаза 06 — Firewall extras (опционально)

| Опция | Описание |
|-------|----------|
| Port forwarding | список `wan_port → lan_ip:port` (tcp/udp) |
| WAN SSH | запретить / allow-list IP / port-knock (advanced) |
| fail2ban | sshd (+ vpn later) |
| SIP ALG | `nf_conntrack_sip` + nft helper (для Zoiper и т.п.) |
| ICMP from WAN | allow / rate-limit / deny |

### Фаза 07 — VPN / туннели

Два раздела: **клиент** (роутер ходит в туннель) и **сервер** (клиенты ходят на роутер).

#### 7.1. VPN-клиент / туннели (можно несколько)

| Тип | Статус v1 | Параметры |
|-----|-----------|-----------|
| WireGuard | **must** | conf/keys, allowedips, route table/policy? |
| OpenVPN (tun) | **must** | client.ovpn / credentials |
| GRE | **must** | local/remote IP, key?, ttl, mtu, routes via gre |
| IPIP | **should** | local/remote, mtu, routes |
| SIT (6in4) | **could** | для IPv6 tunnel brokers |
| L2TP (+ optional IPsec) | **should** | server, user/pass, ipsec PSK |
| IKEv2/IPsec (client) | **should** | strongSwan swanctl |
| PPPoE | уже в WAN; не дублировать |
| EOIP | **could** (linux-eoip) | id, remote, local; пометка «совместимость MikroTik» |
| PPTP | **wont** (небезопасно; только warn+refuse в v1) |
| SSTP / SoftEther | **wont** в v1 |
| ZeroTier / Tailscale / Netbird | **could** как optional module (фаза 1.1) |

Для каждого туннеля:

- поднять systemd unit / netdev
- какие маршруты в туннель (все default / selected prefixes / none)
- policy routing? (fwmark table) — advanced, default off
- MSS clamp автоматически по MTU туннеля

#### 7.2. VPN-сервер

| Тип | Статус v1 | Параметры |
|-----|-----------|-----------|
| WireGuard server | **must** | listen port, адрес пула, peer QR/config gen |
| OpenVPN server | **should** | easy-rsa / существующие certs |
| IKEv2 (strongSwan) | **should** | EAP или certs; Android/iOS |
| L2TP/IPsec server | **could** | |
| PPTP server | **wont** | |

Firewall: открыть нужные UDP/TCP только если сервер включён.

### Фаза 08 — Policy routing / selective bypass (в scope; apply после базы)

**Продуктовое решение:** обход блокировок / selective routing **настраивается в этом проекте**. Wizard собирает ответы сразу; **модуль apply включается в roadmap только после** рабочего базового роутера (WAN/LAN/NAT/DNS/DHCP/VPN-каркас).

1. Включить selective bypass? [n]
2. Пути к спискам доменов и CIDR
3. Целевой туннель / routing table
4. DNS→nftset (если dnsmasq) для доменов
5. Healthcheck fail-open? [Y]

### Фаза 09 — QoS / производительность

| Опция | Default |
|-------|---------|
| Cake SQM на LAN egress | ask, default n |
| Cake на tunnel egress | ask if tunnels |
| GRO off на LAN | ask (только если user подтвердил проблему) |
| Bufferbloat bandwidth limit | optional rate |

### Фаза 10 — IGMP / IPTV proxy

Для пользователей с multicast IPTV от провайдера (`igmpproxy`):

1. Включить IGMP/IPTV proxy? [n]
2. Upstream if — сторона ISP/WAN (default = WAN)
3. Downstream if — LAN или bridge (default = LAN/`br-lan`)
4. quickleave? [Y]
5. altnet CIDR на upstream? [пусто]

### Фаза 11 — Hardening / extras

| Опция | Default |
|-------|---------|
| unattended-upgrades | Y |
| disable root password SSH (keys only) | ask |
| Netdata / node_exporter | n |
| Banner / MOTD с статусом WAN | Y |

### Фаза 12 — Review & apply

1. Показать summary (таблица интерфейсов, WAN mode, LAN CIDR, модули).
2. Записать `answers.yaml`.
3. Baseline + Snapshot.
4. Apply по зависимостям.
5. Verify + health window 60 с (auto-rollback).
6. Предложить reboot если был rename/netplan critical.

## 5. Модель answers.yaml

Минимальная схема (логическая):

```yaml
version: 1
host:
  timezone: Europe/Moscow
  hostname: ubrouter

interfaces:
  naming: eth          # keep | eth | ether | custom
  order: pci           # pci | mac | manual
  map:
    - mac: "aa:bb:..."
      name: eth0
      role: wan
    - mac: "cc:dd:..."
      name: eth1
      role: lan
  bridge:
    enabled: false
    name: br-lan
    members: []

wan:
  interface: eth0
  mode: dhcp           # dhcp | static | pppoe | ipoe | none
  vlan_id: null
  mtu: null
  static: null
  pppoe: null
  ipv6: off

lan:
  interface: eth1      # or br-lan
  cidr: 10.0.0.1/24
  dhcp:
    enabled: true
    pool_start: 10.0.0.1
    pool_end: 10.0.0.1
    lease: 12h
  dns_for_clients: router
  ntp_for_clients: router
  domain: lan

services:
  nat: true
  firewall: true
  dnsmasq: true
  chrony: true
  fail2ban: false
  sip_alg: false
  sqm: false
  igmpproxy: false

igmpproxy:
  enabled: false
  upstream: null          # e.g. eth0 / wan
  downstream: null        # e.g. eth1 / br-lan
  quickleave: true
  altnet: null            # optional CIDR on upstream

dns:
  upstream: ["9.9.9.9", "1.1.1.1"]

firewall:
  wan_ssh: deny        # deny | allowlist | knock
  port_forwards: []
  icmp_wan: rate

vpn:
  clients: []
  servers: []

bypass:
  enabled: false
  domain_files: []
  cidr_files: []
  target: null
  fail_open: true

hardening:
  unattended_upgrades: true
```

Полная JSON Schema: `configs/answers.schema.json`.

## 6. Модули (реализация)

Каждый модуль — каталог `scripts/modules/<name>/` с контрактом:

| Скрипт | Назначение |
|--------|------------|
| `plan.sh` | читает answers → пишет planned files в workdir |
| `apply.sh` | ставит пакеты, копирует конфиги, enable units |
| `verify.sh` | exit 0/1 + человекочитаемый отчёт |
| `rollback.sh` | откат к snapshot модуля |

### 6.1. Обязательные модули v1 (MVP)

1. `interfaces` — naming + map
2. `wan` — netplan WAN
3. `lan` — netplan LAN/bridge + address
4. `sysctl-forward` — ip_forward, rp_filter policy
5. `nat-firewall` — nftables baseline + masquerade
6. `dns-dhcp` — dnsmasq (если включено)
7. `ntp` — chrony (если включено)

### 6.2. Should-have v1

8. `vpn/wireguard` (client+server)
9. `vpn/openvpn` (client; server optional)
10. `vpn/gre`
11. `vpn/ipip`
12. `vpn/l2tp-client`
13. `vpn/ikev2-server` (strongSwan)
14. `hardening` (fail2ban, unattended-upgrades)
15. `qos-sqm`
16. `snapshot`

### 6.3. Could / later

17. `vpn/eoip`
18. `bypass-policy` — **после** базового роутера (WAN/LAN/NAT/DNS/VPN-каркас)
19. `igmpproxy` — IGMP/IPTV (фаза wizard 10)
20. `monitoring`
21. `port-knock`
22. `sip-alg`

### 6.4. Wont (не делаем)

- Wi‑Fi AP / controller / CAPsMAN / mesh
- Web UI
- PPTP

## 7. Зависимости модулей (порядок apply)

```text
snapshot
  → interfaces
    → wan
    → lan
      → sysctl-forward
        → nat-firewall
          → dns-dhcp
          → ntp
          → vpn/*
          → qos-sqm
          → hardening
          → optional/*
```

При ошибке модуля или **регрессии healthcheck в течение 60 с** после apply — автоматический откат к snapshot, сделанному в начале этого apply.

## 8. UX wizard

### 8.1. Режимы

| Режим | Команда | Описание |
|-------|---------|----------|
| Interactive | `./install.sh` | вопросы в TTY |
| Preseed | `./install.sh --answers answers.yaml` | без вопросов |
| Plan only | `./install.sh --plan` | сгенерировать конфиги, не apply |
| Apply | `./install.sh --apply` | применить сохранённые answers |
| Status | `./ubrouter status` | краткий статус WAN/LAN/VPN |
| Rollback | `./ubrouter rollback` | откат последнего snapshot (также срабатывает автоматически после неудачного health window) |

### 8.2. UI

- v1: bash + `read` / optional `whiptail` если установлен
- Цвета/таблицы через общие lib helpers
- Язык UI: **русский** (default) + `UBROUTER_LANG=en`

### 8.3. Безопасность TTY

- Не логировать пароли PPPoE/VPN
- `answers.local.yaml` с секретами в gitignore; в `/etc/ubrouter` права `0600`

## 9. Сеть: эталонные сценарии приёмки

### S1. Minimal home

- 2 NIC, naming `eth`, WAN DHCP, LAN `10.0.0.1/24`, NAT, dnsmasq DHCP+DNS, chrony
- Клиент на LAN получает IP, DNS, ходит в интернет

### S2. Bridge LAN

- 3+ NIC: eth0 WAN, eth1+eth2 → `br-lan`
- DHCP на bridge

### S3. PPPoE WAN

- VLAN 35 + PPPoE, MTU 1492, NAT работает, MSS clamp

### S4. WireGuard server

- WG listen 51820, peer phone, split-tunnel или full-tunnel

### S5. GRE + static routes

- GRE up, маршрут `10.10.0.0/16` via gre; ping remote

### S6. Rename keep

- Без rename: роли на `enp*`, всё остальное работает

### S7. Idempotent re-run

- Повторный `--apply` не ломает lease/SSH сессию (насколько возможно)

## 15. Решения, зафиксированные этим ТЗ

1. Один вход: interactive wizard → answers → modular apply.
2. Именование интерфейсов — первый обязательный шаг.
3. WAN/LAN/bridge — ранний шаг; Multi-WAN failover/LB — цель продукта (базовый — фаза 1.1).
4. Службы и VPN — только по согласию в опроснике; **IGMP/IPTV** — отдельная фаза 10.
5. **Обход блокировок** — модуль `bypass-policy` в общем apply; списки пользователя; fail-open.
6. **Не делаем:** Wi‑Fi controller/AP, Web UI, PPTP.
7. Ubuntu 24.04 LTS amd64 only в v1.
8. Ядро на bash + netplan + nftables + dnsmasq + chrony (+ WG/OVPN/GRE).
9. Apply: snapshot + baseline + post-apply health window с авто-rollback.
